## 1. 问题一：托管引擎"未安装"（检测割裂 + 安装闭环断裂）

### 1.1 根因（带行号）

| # | 根因 | 位置 |
|---|---|---|
| R1-1 | 引擎页"已装版本"**只查托管 prefix** `~/.dsh-desktop/engine`；用户装的是全局 dsh（nvm 前缀），故显示"托管引擎未安装" | `install_service.dart:114-120`（defaultPrefix）、`providers.dart:44-47`（installedVersionProvider）、`engine_page.dart:49`（文案） |
| R1-2 | 实例启动走 `NodeEnv.probe()`：`DSH_CLI` → `where dsh.cmd` → node 同目录（**不含托管 prefix**），探到全局 dsh → 实例其实能跑。两条检测链完全独立 | `node_env.dart:36-74`、`providers.dart:16-22` |
| R1-3 | **安装闭环断裂（真 bug）**：引擎页"安装"写入托管 prefix 后，`instanceManagerProvider` 仍用 probe 出的 PATH 引擎启动实例——文案"安装后实例将以该版本启动"**不成立** | `providers.dart:19-22`、`engine_page.dart:49`、`supervisor.dart:212-220`（用 `env.dshCliJs`） |

### 1.2 方案

- **F1-1 解析顺序改为**：`DSH_CLI`（显式覆盖）→ **托管 prefix**（`InstallService.defaultPrefix` 下探测 bin.js，`InstallService.locateBin` 已有）→ `where dsh.cmd` → node 同目录。托管优先于全局 = "安装即生效"。
- **F1-2 引擎页改双卡片**：
  - 「实例引擎（当前生效）」：`nodeEnvProvider` 的 `dshVersion` + `dshCliJs` 路径 + 来源（托管/PATH/DSH_CLI）；
  - 「托管引擎」：`installedVersionProvider` + 安装/升级/回滚按钮（现状保留）。
  - 文案改事实描述：托管未装时显示"托管引擎未安装（实例当前使用 PATH 引擎 x.y.z）"。
- **F1-3 安装/升级成功后** invalidate `nodeEnvProvider` + `installedVersionProvider`；运行中实例不受影响，SnackBar 提示"新引擎将在实例下次启动生效"。

### 1.3 验收

全局-only 场景：引擎页显示"实例引擎=全局 0.1.1-rc.2（PATH）"+「托管引擎未安装」；引擎页安装成功后，新建实例的详情/日志可见其使用托管 prefix 路径启动。

## 2. 问题二：对话连不上实例

### 2.1 根因（带行号）

| # | 根因 | 位置 |
|---|---|---|
| R2-1 | **端点是冻结 URL 字符串**，而 `port=0` 的实例**每次启动/守护重启都重解端口** → 实例一旦重启（本次实机恰好反复崩溃+守护重启），活动端点指向死端口，前端无限重连 → "连不上" | `providers.dart:62-84`（ActiveEndpoint 存 URL）、`supervisor.dart:207-209`（_resolvePort 每次 start 重解）、`instance_detail_page.dart:167-172`（select 冻结 URL） |
| R2-2 | **无自动连接**：需手动下拉/手输/详情页按钮，与 Gate-A 出口"实例 running 后自动 streaming"不符；用户不清楚要先选端点 | `chat_page.dart:367-414`（下拉+手输）、`instance_detail_page.dart:87-92` |
| R2-3 | **连接错误无原因**：`onError` 吞掉异常，UI 只有"连接异常（自动重连中）"，无法区分拒绝/404/实例未运行 | `connection.dart:130-134`、`chat_page.dart:496-513` |

### 2.2 方案

- **F2-1 端点模型改为「绑定实例 ID」**：`activeEndpointProvider` 存 `instanceId`（手动 URL 模式保留，标记 manual）；新增派生 provider：watch `instanceManagerProvider`+`instanceEventsProvider` → 实时计算 `http://host:port`；端口变化 → 连接自动跟随（重建连接或 `switchEndpoint`，Gate-B 定）。**重启换端口后对话自动恢复，无需重选。**
- **F2-2 自动连接**：进入对话页时，若无活动端点且存在 running 实例 → 自动选第一个；实例转 running 且当前未连接 → 同样自动选中。设置页加开关"自动连接运行中的实例"（默认开）。
- **F2-3 错误可见化**：`DshConnection` 增加 `lastError` 摘要（onError/onDone 捕获，`connection.dart:126-144`）；连接条在 `error` 相位显示原因 + 引导（如 `Connection refused` → "实例未运行或端口已变化，请在实例页启动/重启"）。

### 2.3 验收

实例 crash → 守护重启（端口变化）后，对话页**不重选端点**自动恢复 streaming；未选实例时连接条给出明确引导；error 相位显示具体原因。

## 7. 实机回归追加修正：F2-4 mux WS 协议（v1.1，2026-09-09）

### 7.1 背景

v1.0 修复后实机复测仍"连不上"。用户授权后进行**真实回归**（对运行中实例 `http://127.0.0.1:54272`）：

| # | 实验 | 结果 |
|---|---|---|
| 1 | `netstat` + `GET /` + `GET /api/events.mux` | 端口监听 ✓，`/`=200，mux 路径返回 **426 Upgrade Required + upgrade: websocket**（路径与升级语义正确） |
| 2 | 裸 `WebSocket.connect`（dart:io） | 握手成功（readyState=1），但 **6s 内 0 帧** |
| 3 | `DshConnection.start()`（app 同路径） | 卡在 `connecting`，12s 0 帧、无错误 |
| 4 | REST `session.list` | ok，13 个会话**全部 running=false** |
| 5 | WS 挂着 + REST `session.create` | 帧立刻涌出：projection / event / **session/subscribed**（lastSeq=2），共 7 帧 |
| 6 | 参考客户端 `client.js` `readWebSocket`（10124-10190） | 浏览器端连上后**不发送任何订阅消息**、不依赖首帧判就绪 |

### 7.2 根因

mux WS 是**事件驱动推帧**：无 running 会话时，服务器握手后**静默**；`session/subscribed` 仅在会话创建/启动运行时下发。而 `DshConnection` 以"收到 subscribed 帧"为进入 streaming 的门槛 → 无活跃会话时永久卡在 `connecting` → 会话列表不刷新、历史不装载、UI 呈现"连不上"。旧 fake-server 测试自演服务器（连接即推帧）测不出该缺陷；mux 抓包又取自会先订阅的真实 web 客户端。

### 7.3 修正（F2-4）

- `rpc_client.dart`：`openStream` 增加可选 `onOpen` 回调（WS 握手成功即触发）；
- `connection.dart`：**WS 握手成功即进入 `ConnPhase.streaming`**（= 传输就绪），subscribed 帧仅用于 lastSeq 游标与退避复位；
- **移除 60s 空闲 watchdog**（`idleTimeout` 字段一并删除）：静默是协议常态，误断会照成相位抖动；实例存活性由 L2 HealthProbe（3s 就绪探测 + 僵死自愈）保障。此为对 Gate-B §3.1 的偏离，已在本文档留痕。

### 7.4 验证（对真实实例 `54272`）

```
[phase] +15ms  ConnPhase.connecting
[phase] +53ms  ConnPhase.streaming          ← 原为永久卡死
[check] streaming-reached=true in=109ms
[frame] session/subscribed / projection / event（session.create 触发）
[result] PASS
```

回归脚本沉淀：`packages/client_dart/tool/regress_connect.dart`（对任意运行中实例可复跑）。

## 8. F3-5 对话渲染修正（v1.2，2026-09-09）

用户回报：工具调用只显示一行文字、正文无 Markdown 渲染。

### 8.1 真实帧结构（对运行中实例 probe 采集，`tool/probe_tool_frames.dart`）

| 帧 | 关键字段 |
|---|---|
| `tool/call` | `data={callId,name,arguments}` + `view.view={card:'generic',title:'Glob *',kind:'search',rawInput}`——**有用信息是 title/kind/rawInput，card 只是个类别字符串**（旧实现取 card → 显示"[调用] generic"） |
| `tool/result` | `data.message.content[0]={type:'tool-result',content:[{type:'text',text:7181B}],isError}` + `view.view={shape:'paths',paths[575],truncated,total}` |
| `assistant/message`（权威） | `data.message.content` 可含 `{type:'reasoning',text}` / `{type:'tool-call',id,name,arguments}` / `{type:'text',text}`——**工具调用发生在权威替换之后**（assistant/message seq73 → tool/call 74 → tool/result 75 → step/end 76） |

### 8.2 修正（assembler + UI）

- `assemble.dart`：
  - `ChatBlock` 增加 `toolCallId/toolKind/toolDetail`（text=标题行）；
  - `_applyToolEvent`：call 取 `view.title/kind/rawInput`，result 取 `message.content[].content[].text`（fallback `shape=='paths'` 清单），**按 callId 把 result 归并进 call 块**；回退定位改为**反向搜索最近 assistant**（tool 事件晚于权威替换，旧逻辑只看 messages.last 会丢）；
  - `_applyAssistantMessage` 权威替换：content 解析 text/**reasoning**（新块型 `ChatBlockType.reasoning`）/**tool-call**（与 tool/call 事件按 callId 去重），权威 content 不含工具轨迹，chunk 阶段工具卡显式携带；
- `chat_controllers.dart`：WS 直播帧补传 `payload.view`（与 history 同路——旧代码直播帧丢 view，工具卡拿不到 title）；
- `chat_page.dart` + 新 `shared/markdown_view.dart`：
  - **Markdown**：助手消息**闭合文本块**用 gpt_markdown 渲染（流式中的块/用户消息保持纯文本——流式性能 + 防注入）；围栏代码块深底样式经 `codeBuilder` 统一；
  - **工具卡**：kind 图标（search/read/edit/bash/web…）+ title + 可展开详情（深底等宽，240 上限滚动）；
  - **思考卡**：默认折叠，展开显示 reasoning 全文。

### 8.3 验证（真实 166 帧回放，`tool/replay_frames.dart`）

```
== assistant status=done
  [reasoning] 207B          ← 思考卡
  [tool] title="Glob *" kind=search detail=7181B   ← 聚合后的工具卡
== user / == user / == assistant(streaming…)       ← 顺序与内容正确
```

门禁：两包 analyze 零告警、client_dart 6/6、widget 1/1。渲染效果待用户实机确认（UI 第二轮意见继续收集）。
