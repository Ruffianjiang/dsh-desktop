## 3. L3 协议契约（详细设计重点）

3.1. 端点与传输（服务端 `dsh-host-apiproxy` 注册，Gate-A §10.2/10.3）：
| 项 | 约定 |
|---|---|
| Base | `http://<host>:<port>`，默认 host `127.0.0.1`、port 可配 |
| 上行 | `POST /api/rpc`：JSON body，unary 调用 |
| 资源 | `/api/sessions`、`/api/session-search`、`/api/llm`、`/api/skills`、`/api/subagents`、`/api/goals`、`/api/credentials`、`/api/approvals`、`/api/agent-presets`、`/api/workspace`、`/api/respond` |
| 下行 | SSE：`/api/events.mux`（会话/agent）、`/api/events.host`（host）；streaming fetch、`\n\n` 帧 |
| 信封 | ServerRequest 信封 + MuxFrame/HostFrame（`discriminatedUnion('type')`，zod schema） |

3.2. 契约描述与生成：
1. `packages/contract/` 以 OpenAPI 3.1 描述资源/RPC；SSE 帧以 JSON Schema（一个文件一个 frame 类型）描述。
2. 以本机已装 bundle（`dsh-client-connection`、`events.schema.js`、`sessions.schema.js` 等）为 schema 逆向来源，产出**首版子集**（见 3.3），不追求一次全量。
3. 契约测试：golden 样例（真实抓包/构造帧）跑在 Dart 与 ArkTS 两侧，确保同帧同语义（N9）。

3.3. 首版类型域（P0 全做 / P1 后置）：
| 域 | P0（M1–M3） | P1（后续） |
|---|---|---|
| session | 列表/创建/删除/归档/检索 | — |
| chat | 发消息 RPC、SSE 流式消息帧 | 编辑/重发/中断 |
| event | mux/host 帧、消息增量、agent 状态 | 轨迹回放 |
| approval | ask-user / 审批请求帧、`/api/respond` | 审批历史 |
| subagent | 展开/完成事件 | 托管子代理 |
| skills | 触发/运行状态事件 | 技能配置 |
| settings/llm | 读取默认模型（只读） | 模型切换写入 |

3.4. 连接状态机（`client_dart` / `client_arkts` 共用语义）：
```
Disconnected → Connecting → Connected → Streaming(会话内)
   ↕ 重连（指数退避：1s→2s→…≤30s；游标去重，心跳探活）
Connected → Error/Closed → Disconnected
```
1. 单一 ConnectionController 管理 RPC 池与 SSE 双流（对齐 `dsh-client-connection` 设计）。
2. 事件序号/游标去重：帧带递增 id 时本地去重，缺失触发 gap 重拉策略（M1 定稿细节）。

## 4. L2 引擎管理层详细设计（主客户端 Dart；鸿蒙同语义后置 M5）

4.1. 领域模型：
| 类型 | 字段（草案） |
|---|---|
| `DshEngine` | version、nodeVersion、npmGlobalDir、DSH_HOME、profiles[] |
| `InstanceConfig` | id、alias、profile（默认 web）、port、dataDir、logDir、hostBind(127.0.0.1)、env、autoStart |
| `InstanceStatus` | created/running/starting/stopping/crashed/stopped |
| `InstanceState` | status、pid、port、memKB、startedAt、lastExitCode、lastHeartbeat |

4.2. 状态机（实例）：
```
created → starting ⇄ running ⇄ stopping → stopped
              running → crashed（守护拉起 → starting，退避上限后转 crashed）
```
1. 守护拉起：异常退出 5s 内自动重启，连续失败指数退避（≥3 次后置 crashed 并通知 UI）（N5）。
2. 健康探针：TCP connect + HTTP GET 就绪端点，间隔 3s。

4.3. 服务模块（Dart，`desktop_flutter/lib/engine/`）：
| 模块 | 职责 | 关键接口（草案） |
|---|---|---|
| `NodeProbe` | 探测 node/npm/dsh 版本与可写目录 | `Future<DshEngine> probe()` |
| `InstallService` | `npm i -g dsh@<ver>`；升级/回滚/卸载 | `install(ver)`、`listVersions()` |
| `InstanceSupervisor` | spawn/stop/restart/守护 | `start(cfg)`、`stop(id)`、事件流 |
| `HealthProbe` | TCP/HTTP 探针 | `ping(cfg)` |
| `LogTail` | stdout/stderr 环形缓冲 + 落盘 | `tail(id, lines)`、`export(id)` |
| `RegistryStore` | 实例配置持久化 | 本地 JSON（`~/.dsh-desktop/instances.json`） |

4.4. 引擎进程 spawn 约定：
1. Windows：`Process.start` 隐藏窗口（`createNoWindow`）；其余平台正常后台。
2. 环境注入：`DSH_HOME`、`PORT`、`HOST=127.0.0.1`、`NO_COLOR=1`；日志行带时间戳前缀。
3. 优雅停止：先发停止信号，超时（默认 10s）再 kill。

4.5. 安全（N6/N8）：
1. 凭据不经日志；保存于系统凭据库（Win Credential Manager / macOS Keychain / Linux secret-service）或本地加密文件。
2. 默认绑定 127.0.0.1；「暴露到局域网」为显式开关并强制要求凭据。

## 5. L1 UI 层详细设计（Flutter）

5.1. 模块结构（`desktop_flutter/lib/`）：
```
lib/
├── app.dart / main.dart
├── core/          # 主题、路由、本地化、依赖注入（Riverpod）
├── features/
│   ├── engine/    # 引擎管理页（探测/安装/升级/Profile）
│   ├── instances/ # 实例列表/详情（启停、状态、日志、健康）
│   ├── chat/      # 对话工作台（会话列表+消息流+输入）
│   └── settings/  # 设置（默认端口、数据目录、主题、模型）
└── shared/        # 组件（Markdown 渲染、代码块、虚拟列表、气泡）
```
5.2. 技术选型（待 Gate-B 评审确认）：
| 项 | 候选 | 建议 |
|---|---|---|
| 状态管理 | Riverpod / Bloc | **Riverpod**（轻量、编译期安全，适合中小团队） |
| Markdown | flutter_markdown / gpt_markdown 类 | 评审时按流式增量渲染实测选型（M3 前定） |
| 虚拟列表 | flutter ListView/`flutter_tree`/自定义 | 内置 ListView.builder + 滚动锚定 |
| HTTP/SSE | `http`/`dio` + 手写 SSE 流 | 基于 `dart:io HttpClient` 的 streaming fetch 封装 |
| 窗口/托盘 | `window_manager`、`tray_manager`、`launch_at_startup` | M3 前实测兼容性 |

5.3. 首屏信息架构（M3 版）：
```
左侧导航：引擎 / 实例 / 对话 / 设置
对话工作台：会话列表（左）| 消息流（中）| （工具/审批面板按需右侧）
```
5.4. 交互规格引用 F4（会话、流式渲染、工具轨迹、审批、附件），不在此重复，Gate-B 评审后按 F4.1–F4.5 拆细。

| `common` | 主题、常量、工具 |

6.2. **待启动预研清单（原 M1.5 / R6）**——届时在真机/模拟器逐项验证并产出结论：
1. 应用侧能否运行 Node（ohos 专用构建）或 spawn 子进程执行 npm；
2. 能否常驻守护（后台任务/服务能力）并监听本地端口；
3. 网络权限（连接本机/局域网 dsh 端点）；
4. 结论分支：通过→F6.2 应用内托管；不通过→F6.2 转「远端托管实例管理」（端点模型不变）。

6.3. UI 交互规格（立项依据）：F6.3 复用 F4 交互与渲染规格（ArkTS 独立实现：ArkUI 列表/流式文本）。
