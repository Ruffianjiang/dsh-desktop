## 3. 目标与非目标

### 3.1 目标（本迭代，编号 GF2-*）

| 编号 | 目标 | Gate 依据 |
|---|---|---|
| GF2-1 | **守护拉起**：异常退出 ≤5s 自动重启，指数退避，连续失败 ≥3 次置 `crashed` 并广播事件；手动 start 复位 | Gate-B §4.2.1、N5 |
| GF2-2 | **持续心跳**：独立 `HealthProbe`，TCP + HTTP GET 就绪端点，3s 间隔；结果写 `lastHeartbeat` | Gate-B §4.2.2 |
| GF2-3 | **restart**：stop→start 组合语义；重置守护退避计数 | Gate-A F2.2 |
| GF2-4 | **LogTail**：环形缓冲 + 文件双写；`tail(id, lines)` / `export(id)`；行带时间戳前缀 | Gate-B §4.3/§4.4.2 |
| GF2-5 | **RegistryStore 增强**：`upsert/remove/get`；`autoStart=true` 实例在宿主启动时自动拉起 | Gate-A F2.1 |
| GF2-6 | **状态事件流**：`Stream<InstanceEvent>` broadcast（状态/心跳/退出），供 UI 订阅 | Gate-B §4.2「通知 UI」 |

### 3.2 非目标（本迭代明确不做）

1. UI 层实现（M3）——本迭代只保证数据与事件接口就绪；
2. `memKB` 内存采集——`dart:io` 无跨平台进程内存查询，Windows 需 Dart FFI 调 win32（PROCESS_MEMORY_COUNTERS），涉及平台代码，列 BQ3 默认后置；
3. 凭据库与局域网暴露开关（N6/N8，后续迭代）；
4. 远端/跨机实例管理（N1）；
5. 系统开机自启（F5.2，另迭代）。

## 4. 方案设计

### 4.1 状态机修订（关键）

```
created → starting ⇄ running ⇄ stopping → stopped
              ↓ 异常退出（非 stopping 引发）
        Guardian 退避重启（1s → 2s → 4s …，期间仍为 starting）
              ↓ 连续失败 ≥3 次
           crashed（终态：放弃守护，需手动 start 复位）
```

- **不新增枚举值**：保持 Gate-B §4.1 六态不变；「守护重启中」用 `starting` + 新字段 `guardianAttempts` 表达，避免 UI 侧枚举膨胀（BQ7）。
- `crashed` 语义收窄为「放弃守护的终态」；手动 `start()` 复位为 `starting` 并清零计数。

### 4.2 Guardian（守护拉起，GF2-1）

- 挂接点：现有 exitCode 回调（`supervisor.dart:57-65`）——**非 `stopping` 引发的退出**视为异常退出，转入守护流程；主动 `stop()` 置 `stopping` 以抑制守护。
- 策略：异常退出后 **1s 内首次重启**（满足 N5 ≤5s），失败后 2s/4s/8s… 指数退避（上限 30s）；**连续失败 3 次**置 `crashed`、停守护、广播事件。
- 手动 `start()` 清零连续失败计数。
- 重启前端口复核：`port==0` 重新分配；固定端口被占 → 该次启动失败计入守护失败（防无意义重启循环）。

### 4.3 HealthProbe（独立模块，GF2-2）

- 新文件 `lib/src/health_probe.dart`；启动期就绪探测**移植**自 `_waitReady`（`supervisor.dart:107-129`），进入 running 后每 **3s** 探测。
- 探测方式：TCP connect + `GET /`（就绪判据沿用 HTTP 200–499；不用 `/api/events.*`——SSE 会挂住连接）。
- **僵死自愈（BQ2 默认策略）**：连续 3 次心跳失败（≈9s）→ 判定疑似僵死 → kill 进程交 Guardian 重启（探针触发的 kill 同样计入守护失败计数，天然防无限循环）；备选策略「仅告警不重启」。
- 心跳结果写 `lastHeartbeat` 并发 `Heartbeat` 事件；`stopping/stopped` 状态下探针挂起。

### 4.4 LogTail（GF2-4）

- **双写**：stdout/stderr 行 → 内存环形缓冲（默认 2000 行，BQ4）+ 现有文件追加（保留，`supervisor.dart:26-29` 不变）。
- 行格式补时间戳前缀（ISO8601，对齐 Gate-B §4.4.2——现状缺失）。
- API：`tail(id, lines)` 读环形缓冲；`export(id, [path])` 返回完整日志文件路径（文件本就完整落盘，导出即拷贝/返回路径）。

### 4.5 RegistryStore 增强（GF2-5）

- 新增 `upsert(cfg)` / `remove(id)` / `get(id)`；`load/save` 与 schemaVersion=1 不变（字段无迁移需求）。
- `autoStart` 拉起：提供库级能力（按 `autoStart==true` 过滤并逐个 `start`，失败不阻断其他实例）；触发时机默认「宿主应用启动时调用」（BQ5），系统自启归 F5.2。

### 4.6 状态事件流（GF2-6）

- `Stream<InstanceEvent> get events`（broadcast StreamController）。
- 事件变体：`StatusChanged(from, to, pid, port)`、`Heartbeat(ok, latencyMs)`、`Exited(exitCode, guardianAction)`。
- 发射点统一：start/stop/restart/Guardian/Probe 全部经事件流对外；**日志行默认不进事件流**（防洪泛，UI 后续用 tail 轮询/文件 watch，BQ 候选不单列）。

### 4.7 InstanceState 补字段

- 新增 `lastHeartbeat: DateTime?`、`guardianAttempts: int`；
- `memKB`：默认不做（BQ3），面板先展示 pid/port/启动时长。

## 5. 关键接口草案

```dart
class InstanceSupervisor {
  Stream<InstanceEvent> get events;                 // 新增
  Future<InstanceState> start(InstanceConfig cfg);  // 已有；挂守护 + 清零退避
  Future<int?> stop();                              // 已有；超时对齐（BQ6）
  Future<InstanceState> restart();                  // 新增
  LogTail get logTail;                              // 新增（当前单实例 supervisor 语义不变）
}

class HealthProbe {
  HealthProbe({required this.onEvent, this.interval = const Duration(seconds: 3), this.failureThreshold = 3});
  void attach(InstanceConfig cfg, int port);        // running 后启用
  void detach();                                    // stopping/stopped 时挂起
}

class LogTail {
  List<String> tail(int lines);
  String export([String? path]);                    // 返回日志文件路径
}

extension RegistryStoreX on RegistryStore {          // 或直接加在 RegistryStore
  void upsert(InstanceConfig cfg);
  void remove(String id);
  InstanceConfig? get(String id);
}
```

## 6. 任务拆分（TF1–TF6，按依赖序，可直接开工）

| 编号 | 任务 | 依赖 | 出口 |
|---|---|---|---|
| TF1 | 事件流 + `InstanceState` 补字段 + 全量状态埋点 | — | 状态变更可订阅 |
| TF2 | Guardian 守护拉起 + 退避 + `crashed` 终态 + 端口复核 | TF1 | kill -9 子进程后 ≤5s 自动重启（实测） |
| TF3 | `HealthProbe` 独立模块 + 心跳 + 僵死自愈 | TF1 | 杀进程/假死场景心跳与自愈事件正确 |
| TF4 | LogTail（环形 + 时间戳 + tail/export） | TF1 | tail/export 可用且文件完整 |
| TF5 | RegistryStore `upsert/remove/get` + autoStart 拉起 | TF2 | 配置增删改查 + autoStart 批量拉起实测 |
| TF6 | `restart` API + 优雅停止超时对齐 + `tool/selfcheck_lifecycle.dart` | TF2/TF3 | 自检全过（含崩溃拉起与 crashed 复位） |

6.1. **自检扩展** `tool/selfcheck_lifecycle.dart`：启动 → `kill -9` 子进程 → 断言 ≤5s 重启至 running → 注入坏 dsh 入口模拟连续失败 → 断言 3 次后 `crashed` → 手动 `restart` 复位 → running → 全链事件断言。真实起停一轮，预计 2–3 分钟。
6.2. 全部任务**仅开发不提交**（禁止自动提交）；提交经确认后按 `feat:`/`fix:` + P0/P1/P2 拆分子提交，代码与文档同一提交。

## 8. 风险

| 编号 | 风险 | 等级 | 缓解 |
|---|---|---|---|
| RF2-1 | 守护与探针竞态：stop 过程中心跳误判僵死 | 中 | `stopping/stopped` 状态屏蔽探针与守护（单一状态机裁决） |
| RF2-2 | 固定端口被占 → 重启循环 | 中 | 重启前端口复核（§4.2）；失败计入守护计数，3 次即 crashed |
| RF2-3 | 日志洪泛（dsh 高频输出）拖慢事件循环 | 低 | 环形缓冲 O(1)；日志行不进事件流 |
| RF2-4 | dsh rc 版升级后退出行为/就绪端点变化 | 中 | 探测判据宽松（200–499）+ 自检真机回归 |

## 9. BQ 结论（v1.0 确认，2026-09-04，按建议默认闭环）
